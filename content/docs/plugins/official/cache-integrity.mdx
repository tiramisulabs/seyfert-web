---
title: Cache Integrity
description: Prevent persistent cache entries from becoming ghost data after a process restart.
---

`@slipher/cache-integrity` makes data from an earlier process invisible until the current process writes it again.
It is intended for cache adapters whose storage can outlive the bot process.

The plugin does not fetch from Discord or delete old storage. A hidden entry behaves like a normal cache miss, so the
resource's configured cache `flow` still decides whether an on-demand REST request is allowed.

## Installation

```sh
pnpm add @slipher/cache-integrity
```

Requires Seyfert v5.

## Setup

Add the plugin and configure the persistent adapter before `client.start()`:

```ts
import { createClient } from '@redis/client';
import { cacheIntegrity } from '@slipher/cache-integrity';
import { RedisAdapter } from '@slipher/redis-adapter';
import { Client, definePlugins } from 'seyfert';

const redis = createClient({ url: process.env.REDIS_URL });
const plugins = definePlugins(cacheIntegrity());

declare module 'seyfert' {
	interface SeyfertRegistry {
		plugins: typeof plugins;
	}
}

const client = new Client({ plugins });

client.setServices({
	cache: {
		adapter: new RedisAdapter({
			client: redis,
			namespace: 'bot-cache',
		}),
	},
});

await client.start();
```

There are no coordinator, namespace, or plugin-order options. Cache integrity wraps whichever adapter is configured
when plugin setup runs.

## Process generations

Every plugin installation starts with an empty, in-memory visibility index. Existing values and relationships remain
in the backing adapter, but reads cannot return them. A successful write through the wrapper marks the affected entry
as part of the current process generation.

| Operation | Behavior |
| --- | --- |
| `get`, `bulkGet`, `scan` | Return only values written by this process. |
| Relationship reads | Return only relationships written by this process. |
| `set`, `bulkSet` | Persist the value, then make it visible if the write succeeds. |
| `patch`, `bulkPatch` | Replace hidden values so stale fields cannot survive the first current write; patch visible values normally. |
| Removals and `flush` | Change visibility only after the backing operation succeeds. |

This gives a simple restart contract: persistence alone is never enough to make an entity current. Gateway and REST
cache writes naturally repopulate visibility as Seyfert observes current Discord data.

<Callout type="info">
The plugin provides logical isolation, not garbage collection. Old physical entries may remain in the adapter until
the application or adapter removes them.
</Callout>

## Multiple processes and workers

Visibility belongs to the process running the plugin and is tracked by key. The first successful local write admits
that key for the rest of the plugin generation. A later write that bypasses the wrapper—including a write from another
process—can therefore replace the admitted value.

Use one writer per keyspace, or partition shared storage so processes do not overwrite each other's admitted keys.
Cache integrity does not provide distributed isolation, ownership leases, or fencing.

<Callout type="warn">
Seyfert's RPC-backed `WorkerAdapter` is not supported. Seyfert v5 resolves worker cache responses through the exact
adapter instance installed on the client, so replacing it with a wrapper would leave requests pending until timeout.
Configure cache integrity only where the client owns a real adapter.
</Callout>

## Lifecycle and limitations

Configure the adapter before starting the client. During plugin teardown, cache integrity restores the original
adapter only if its wrapper is still installed, so it does not overwrite a later adapter replacement.

Writes that bypass Seyfert's installed cache adapter do not admit new keys. They can still replace keys that this
process already admitted. The plugin has no status API and performs no background reconciliation.

Using it with Seyfert's `MemoryAdapter` is supported but redundant because that adapter already starts empty.
